# Инструкция Social Contact Collector 0.6.1

Это инструкция для запуска на Windows через Docker и PostgreSQL. Для телефона используйте отдельный файл `TERMUX_ACODE_GUIDE_RU.md`.

Программа собирает разрешённые контакты из социальных сетей, показывает лиды в панели управления и позволяет создавать кампании с несколькими вариантами сообщений.

## Публикация комментариев VK

В файле `.env` заполните переменную одной строкой:

```env
VK_COMMENT_ACCOUNTS_JSON=[{"id":"main","label":"Основной VK","token":"ВАШ_ПОЛЬЗОВАТЕЛЬСКИЙ_ТОКЕН","dailyLimit":10}]
```

Для нескольких аккаунтов добавьте несколько объектов внутрь массива. `id` должен быть уникальным, `label` отображается в панели, `dailyLimit` задаёт локальный дневной предел. Не публикуйте `.env` и не отправляйте токены другим людям.

После изменения `.env` выполните `docker compose up --build -d`. Откройте `http://localhost:8080/dashboard`, затем выберите аккаунт, вставьте полную ссылку на запись, введите текст и нажмите «Создать черновик». Проверьте запись в журнале и отдельно нажмите «Подтвердить и опубликовать».

Статус `Опубликован` означает успешный ответ VK; появится ссылка на комментарий. Статус `Ошибка` содержит ответ API. Полностью автоматическая публикация без подтверждения не предусмотрена.

## 1. Что потребуется

- Windows 10 или Windows 11;
- Docker Desktop;
- PowerShell;
- свободный порт `8080`;
- минимум 2 ГБ свободной оперативной памяти;
- токены социальных сетей для реального сбора и отправки сообщений.

Для просмотра панели без подключения социальных сетей токены не нужны.

## 2. Распаковка

Распакуйте ZIP-архив, например, в папку:

```text
C:\Users\User\Documents\social-contact-collector
```

Откройте PowerShell и перейдите в неё:

```powershell
cd "C:\Users\User\Documents\social-contact-collector"
```

## 3. Создание настроек

Создайте рабочий файл `.env`:

```powershell
Copy-Item ".env.example" ".env"
```

Создайте безопасный ключ администратора и запишите его в `.env`:

```powershell
$ApiKey = [guid]::NewGuid().ToString("N") + [guid]::NewGuid().ToString("N")

(Get-Content ".env") `
  -replace '^ADMIN_API_KEY=.*$', "ADMIN_API_KEY=$ApiKey" |
  Set-Content ".env" -Encoding utf8

$ApiKey
$ApiKey | Set-Clipboard
```

Сохраните этот ключ. Он потребуется для входа в панель и обращения к API.

## 4. Первый запуск

Запустите Docker Desktop и дождитесь, пока Docker перейдёт в рабочее состояние.

В PowerShell выполните:

```powershell
docker compose up --build -d
```

Проверьте контейнеры:

```powershell
docker compose ps
```

В списке должны присутствовать контейнеры `api` и `postgres` без постоянных перезапусков.

Проверьте API:

```powershell
Invoke-RestMethod "http://localhost:8080/health"
```

Ожидаемый ответ:

```text
status : ok
version: 0.6.1
storage: postgres
```

## 5. Панель управления

Откройте в браузере:

```text
http://localhost:8080/dashboard
```

В шапке панели сразу видно поле `API-ключ`. Вставьте значение `ADMIN_API_KEY`, созданное ранее, и нажмите `Сохранить`.

В панели доступны:

- общее количество лидов;
- количество лидов с контактами;
- средний Lead Score;
- распределение по платформам;
- поиск и фильтрация;
- выгрузка CSV;
- создание шаблонов сообщений;
- создание и запуск кампаний.

## 6. Обновление с предыдущей версии

Если PostgreSQL уже запускался с версией `0.3.x`, примените новые таблицы без удаления данных:

```powershell
Get-Content ".\db\001_init.sql" |
  docker compose exec -T postgres psql -U collector -d collector
```

После этого перезапустите API:

```powershell
docker compose restart api
```

Не выполняйте `docker compose down -v`, если хотите сохранить существующие лиды: параметр `-v` удаляет базу данных.

## 7. Настройка социальных сетей

Откройте `.env`:

```powershell
notepad ".env"
```

Заполните доступные параметры:

```dotenv
VK_CALLBACK_SECRET=
VK_CONFIRMATION_CODE=
VK_ACCESS_TOKEN=
VK_API_VERSION=5.199

TELEGRAM_WEBHOOK_SECRET=
TELEGRAM_BOT_TOKEN=

META_VERIFY_TOKEN=
META_APP_SECRET=
META_PAGE_ACCESS_TOKEN=
META_GRAPH_VERSION=v23.0
```

После изменения `.env` пересоздайте API-контейнер:

```powershell
docker compose up -d --force-recreate api
```

### Адреса webhook

```text
Telegram:  https://ВАШ-ДОМЕН/webhooks/telegram
VK:        https://ВАШ-ДОМЕН/webhooks/vk
Meta:      https://ВАШ-ДОМЕН/webhooks/meta
```

Социальные сети не принимают `localhost` как внешний webhook. Для реального подключения нужен сервер с публичным HTTPS-доменом.

## 8. Создание шаблона сообщения

В панели заполните блок `Новый шаблон`:

1. Укажите название.
2. Выберите платформу или `Все платформы`.
3. Напишите один или несколько вариантов сообщения.
4. Разделяйте варианты отдельной строкой `---`.
5. Нажмите `Сохранить шаблон`.

Пример:

```text
Здравствуйте, {{firstName}}! Есть инвестиционное предложение. Можно отправить презентацию?
---
Добрый день, {{displayName}}! Предлагаем рассмотреть перспективный проект. Интересно получить подробности?
---
Здравствуйте! Нашли ваш профиль в {{platform}}. Можем направить краткую информацию по инвестиционному проекту?
```

Разрешённые переменные:

- `{{firstName}}` — имя;
- `{{displayName}}` — отображаемое имя;
- `{{username}}` — имя пользователя;
- `{{platform}}` — социальная сеть;
- `{{profileUrl}}` — ссылка на профиль.

Программа стабильно распределяет варианты между получателями, чтобы один лид не получал случайный новый вариант при повторном формировании кампании.

## 9. Создание кампании

В блоке `Новая кампания`:

1. Введите название кампании.
2. Выберите созданный шаблон.
3. Перечислите платформы через запятую.
4. Установите минимальный Lead Score.
5. Выберите дату и время отправки.
6. Нажмите `Создать и запустить`.

Пример платформ:

```text
telegram,vk,instagram,facebook
```

В очередь попадают только получатели:

- подтвердившие контакт; либо
- уже начавшие разрешённый диалог;
- отсутствующие в стоп-листе;
- соответствующие минимальному Lead Score;
- не получавшие сообщение за последние 24 часа.

## 10. Поддержка отправки

| Платформа | Режим |
| --- | --- |
| Telegram | Автоматически через Bot API, если пользователь ранее взаимодействовал с ботом |
| VK | Автоматически через API сообщества при наличии разрешения на сообщения |
| Facebook | Автоматически через Meta Messaging в разрешённом окне диалога |
| Instagram | Автоматически для профессионального аккаунта в пределах разрешений Meta |
| X | Ручная проверка без разрешённого DM API |
| LinkedIn | Ручная проверка без одобренного партнёрского доступа |
| Дзен | Ручная проверка |
| Pinterest | Ручная проверка |
| Reddit | Ручная проверка либо отдельное разрешённое приложение |
| Quora | Ручная проверка |

Программа не обходит ограничения платформ и не извлекает закрытые контакты.

## 11. Повторные попытки и ошибки

При временной ошибке отправка повторяется автоматически с увеличением задержки. После достижения лимита попыток сообщение получает статус `failed`.

Если автоматическая отправка для платформы не настроена, сообщение получает статус `manual_review`.

## 12. Выгрузка лидов

Нажмите `Скачать CSV` в панели либо выполните:

```powershell
$Headers = @{ "x-api-key" = $ApiKey }
Invoke-WebRequest "http://localhost:8080/api/leads.csv" -Headers $Headers -OutFile ".\leads.csv"
```

## 13. Диагностика

Состояние контейнеров:

```powershell
docker compose ps
```

Логи API:

```powershell
docker compose logs -f api
```

Логи PostgreSQL:

```powershell
docker compose logs -f postgres
```

Повторная сборка:

```powershell
docker compose up --build -d
```

Проверка занятого порта:

```powershell
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
```

## 14. Остановка

Остановить программу без удаления данных:

```powershell
docker compose down
```

Запустить снова:

```powershell
docker compose up -d
```

## 15. Безопасность

- не публикуйте `.env`;
- не отправляйте токены и `ADMIN_API_KEY` посторонним;
- не добавляйте `.env` в Git;
- используйте HTTPS;
- периодически меняйте токены;
- храните подтверждение согласия на получение сообщений;
- обеспечьте понятную возможность отказаться от рассылки;
- соблюдайте правила социальных сетей и требования законодательства о персональных данных и рекламе.
